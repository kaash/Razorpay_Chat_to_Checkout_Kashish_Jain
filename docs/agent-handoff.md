## 1. What this is (one paragraph)
**Meera** sells kurtis on Instagram and WhatsApp and already uses Razorpay Payment Links. When a buyer agrees in a DM, Meera copies the order into Razorpay by hand.

**Chat to Checkout** lets her share just that chat (pasted text or a screenshot):
- **AI** reads it and proposes the order, with the exact words behind each detail.
- **Code** checks every quote, applies the colour-ambiguity rule and prices the order from her own list in integer paise.
- **She** approves one card. A standard Payment Link is created, and a reply is copied for her to send herself.
- **Status** (Paid / Unpaid) comes from Razorpay.

The AI never sets money and never sends anything. "Copied" never means "Sent".

**How the page decides its mode (no code change needed):** at load it calls `GET /api/health`.
- If AI is on, the live tab sends text or screenshots to `/api/draft`. A screenshot goes straight to Claude's vision; Tesseract isn't used.
- If payments are on, **Create** calls `/api/links`, the reply carries the real `short_url`, and the side card shows **Open the payment page** (real Razorpay test checkout), **Refresh status** and **Cancel link**. Status polls every 8 s.
- If `/api/health` fails (static hosting, file://), everything falls back to the in-browser rules and simulated buyer. Nothing breaks.
- The **Sample demo** tab is scripted and never calls the server.

### Task 2: Verify the two external APIs against current docs before using real keys
I wrote these from memory. Confirm and adjust if needed.

**Claude Messages API** (`lib/anthropic.js`):
- endpoint `https://api.anthropic.com/v1/messages`
- headers `x-api-key` and `anthropic-version: 2023-06-01`
- `tools` with `input_schema` and `tool_choice: {type:"tool", name:"record_draft"}`
- image blocks `{type:"image", source:{type:"base64", media_type, data}}`
- **Model ID:** default `claude-sonnet-5-5`. Check the current IDs at https://docs.claude.com/en/docs/about-claude/models/overview and set `CLAUDE_MODEL` if different. Use a Sonnet-class model with vision. A Haiku-class model is cheaper; run the eval on both if the owner wants. Haiku had 1 silent error before the colour rule and 0 after.
- If the API rejects `["string","null"]` union types in the tool schema, switch to `anyOf` or `nullable` forms. Don't drop fields.

**Razorpay Payment Links API** (`lib/razorpay.js`):
- `POST /v1/payment_links`, `GET /v1/payment_links/{id}`, `POST /v1/payment_links/{id}/cancel`, with Basic auth (key_id:key_secret)
- fields `amount` (paise), `currency`, `accept_partial`, `reference_id` (unique, ≤40 chars), `expire_by` (unix seconds), `description`, `customer.name`, `notify`, `reminder_enable`, `notes` (≤15 keys, ≤256 chars each)
- statuses `created | partially_paid | expired | cancelled | paid`
- Docs: https://razorpay.com/docs/api/payments/payment-links/
- Confirm the **test-mode payment details** (UPI ID, test cards) at https://razorpay.com/docs/payments/payments/test-card-upi-details/. The side card mentions `success@razorpay`; change that text in `frontend/src/7-live.js` (`simCard`) if the docs say otherwise.

## 4. Hard rules (do not break these)
1. **UI is frozen.** Don't redesign the page, change copy tone, or add frameworks. Only fix bugs. Edit `frontend/src/*`, then `npm run build`; never edit `public/index.html` by hand.
2. **AI never sets money.**
   - Prices come from `DATA.catalogue`.
   - Totals are recomputed in `lib/order.js`.
   - A buyer's price ask is recorded, never applied.
   - The browser's `expected_total_paise` must equal the server total, or the link is refused.
3. **Every AI field needs a real quote** from the chat (`lib/guard.js`), and the colour rule runs in code even when the model is confident. Do not loosen the thresholds (0.85 field, 0.80 product, 0.15 margin).
4. **Test mode only.** Never use live Razorpay keys.
5. **No secrets in the browser or the repo.** Keys live only in Vercel env vars or `.env`.
6. **Honest labels stay.** "Concept prototype … not an official Razorpay product". The "Simulated" tags stay on sending in Instagram/WhatsApp and the share sheet. "Copied", never "Sent".
7. **The chat is untrusted input.** Keep the injection guard in the prompt and the code checks.
8. **Keep the static fallback working.** `submission/prototype-standalone.html` and `public/index.html` opened as `file://` must still run (rules + simulated payments). The tests check this.
9. Don't store chats or screenshots server-side. Don't add logging of request bodies.

## 6. If something goes wrong
| Problem | Fix |
|---|---|
| `/api/health` 404 on Vercel | Check the `api/` folder is at the repo root and the project root directory is the repo root |
| Claude 400 on the tool schema | Adjust union types (see Task 2). Re-run `npm test`. |
| Claude 401 / 403 | Wrong key or no credit. The page falls back to rules and logs "AI unavailable". |
| Razorpay 401 | Using live keys, or a key/secret mismatch |
| Razorpay rejects a field | Fix the body in `lib/razorpay.js` per the docs; keep amounts in paise |
| Request too large on screenshots | Already downscaled to 1600 px JPEG; lower to 1280 in `fileToDataUrl` |
| Rate-limit hits during judging | Raise `RATE_PER_DAY` in Vercel. The spend limit is the real guard. |
| Out of time | Keep the Vercel deploy with AI only (leave the Razorpay keys unset). The page then shows real AI and simulated payments, still labelled honestly. |
